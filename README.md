# ماركت الواحة — متجر سوبر ماركت إلكتروني (عربي RTL)

متجر كامل لسوق مصري: واجهة عربية، أسعار بالجنيه، سلة وطلب عبر واتساب، فواتير، ولوحة إدارة للمالك. الواجهة HTML/CSS/JS عادية بدون إطار عمل، والخلفية Supabase (PostgreSQL + Auth + Storage + Edge Functions).

```
web/                    الموقع (ملفات ثابتة)
  index.html            المتجر           admin.html   لوحة الإدارة      invoice.html  الفاتورة
  css/ js/              js/config.js هو الملف الوحيد الذي تعدّله (رابط Supabase والمفتاح العام)
supabase/
  migrations/001-004    الجداول، الدوال، سياسات RLS، الأقسام الـ 22
  bootstrap_owner.sql   إنشاء المالك الأول (مرة واحدة من SQL Editor)
  functions/whatsapp-notify/   إرسال اختياري عبر WhatsApp Cloud API
  tests/                اختبارات الأمان والطلبات لقاعدة البيانات
docs/                   SETUP.md · DEPLOYMENT.md · TESTING.md
```

## المبادئ الأمنية
- كل الأسعار والمخزون والإجماليات تُحسب في قاعدة البيانات (`create_order`)؛ المتصفح يرسل المنتج والكمية فقط.
- الطلبات لا تُنشأ إلا عبر هذه الدالة؛ الإدراج المباشر في الجداول مرفوض بسياسات RLS.
- المالك وحده يتحكم بالمنتجات والأسعار والأقسام والموظفين؛ صلاحيات الموظف محصورة بـ *الطلبات* و*التقارير*.
- سعر التكلفة في جدول منفصل للمالك فقط.
- لا أسرار في الواجهة؛ توكن واتساب في Supabase Secrets فقط.
- طلبات الزوار تُقرأ بتوكن سري لكل طلب، والفواتير والطلبات لا تُحذف.

## ابدأ من هنا
1. `docs/SETUP.md` ← إنشاء المشروع وتشغيل SQL وإنشاء المالك وربط البريد/SMS/واتساب.
2. `docs/DEPLOYMENT.md` ← النشر والنسخ الاحتياطي والاستعادة.
3. `docs/TESTING.md` ← قائمة الاختبار قبل الإطلاق.

## حدود معروفة
- لا صور منتجات مرفقة: لا يمكن توفير صور تجارية مرخّصة تلقائياً. يرفع المالك صوره من لوحة الإدارة، وتظهر أيقونة بديلة للمنتج بلا صورة.
- الدخول برمز الهاتف والإرسال التلقائي عبر واتساب API يحتاجان حسابات خارجية (مزود SMS، Meta Business) وتعمل فقط بعد إعدادها.
- PDF الفاتورة عبر "حفظ كـ PDF" من نافذة الطباعة في المتصفح.
